# 和序 HIS 门诊业务管理系统课程设计报告

版本：功能展示版，2026-10-29。分支：dev_lboverfys。班级、成员与学号请提交者按真实情况填写。

## 一、选题与目标

本项目以老师“根据2002医院信息系统功能规范选择题目，完成课程设计，提交代码、演示PPT和相关文档”的要求为依据，选择门诊医生工作站、门诊收费、门诊药房三个分系统的部分功能。患者档案、排班和挂号支撑一次完整的门诊业务。

本版重点是现场可操作、可讲解的功能。演示者可以先看经营图表，再完成医生接诊、记录病情、开方、收费打印、药师发药，最后查看业务变化。不需要公网地址。

需求主题参照教师第4～12课课件整理。尚未取得2002年规范全文逐条核验，不编造条款编号，不将课程项目称为生产医疗系统。

## 二、功能与页面

| 业务部分 | 已有基础 | 本版可见升级 |
|---|---|---|
| 门诊医生工作站 | 本人待诊、多药处方、自动划价、草稿编辑与提交 | 接诊看板、诊疗记录、常用诊断检索、患者就诊时间线、处方打印 |
| 门诊收费 | 待收费队列、核对明细、收费记录 | 收费方式、收费记录搜索、未发药全额退费、收费凭证打印 |
| 门诊药房 | 药品档案、批次入库、已收费处方发药 | 低库存/近效期/过期提醒、可用量与账面量对照、出入库流水 |
| 管理与支撑 | 患者、排班挂号、CSV导入、角色、审计 | 经营趋势、科室分布、日期区间统计、CSV报表导出、丰富展示场景 |

### 1. 接诊看板

页面显示时钟、候诊数量、接诊数量和完成数量，分区列出候诊与接诊中的患者。医生点击“开始接诊”，患者状态改为就诊中，再从卡片进入诊疗工作台。时钟每秒更新，列表每15秒刷新。页面明确提示：统计最近100条挂号中的今日记录，医生只看本人范围。

### 2. 诊疗记录与常用诊断

医生填写主诉、现病史、既往史、过敏史和查体意见，可使用标注为虚构的教学示例。常用诊断支持名称或ICD-10编码检索，提供12项教学示例，仍可手动录入。保存成功有明确提示。提交处方后本次文书锁定。

### 3. 患者就诊时间线

从患者档案或诊疗记录进入时间线，按时间回看就诊日期、医生、诊断、主诉、处方状态和费用，并可打开处方打印页。管理员查看患者记录，医生只查看自己接诊的记录。本功能属于课程门诊记录，不声称完整电子病历认证。

### 4. 收费、退费与打印

收费时选择现金、银行卡或模拟扫码，金额继续由药品单价快照计算。收费记录可按患者搜索和按状态筛选。只有已收费、未发药且能追溯本轮出库批次的处方支持全额退费，原收费凭证保留，另存退费原因和时间，库存退回原批次。

已发药处方不提供退费入口，接口也拒绝该操作。退费不释放已经使用的号源，重新诊疗应另挂号。旧历史处方若缺少批次出库记录，系统明确拒绝自动回库。

处方笺和收费凭证提供A4打印预览，使用浏览器“打印 / 保存为 PDF”。凭证包含患者、诊断、药品、金额等内容；已退费凭证另有退费标记。全部带有教学说明，不作为真实处方、发票或支付证明。

### 5. 药房库存中心

预警按低库存、近效期、已过期筛选。可用量不包含过期批次，低库存阈值为10，近效期为30天。流水记录入库、导入入库、收费出库和退费回库，展示药品、批号、数量变动、批次结余、关联处方和操作人。旧库迁移生成“迁移期初”，不编造历史出库明细。

### 6. 经营数据看板

支持今日、近7天、近30天和自选日期（最多90天）。页面包括有效挂号、收费、退费、净收入四项指标、门诊量和净收入趋势、科室分布、每日明细与CSV导出。所有数字查询当前数据库，不在页面硬编码医院经营结果。

收费按发生日计入，退费按退费发生日扣减。净收入等于收费减退费，跨日退费可能出现某日净额为负。教学初始化提供7天虚构业务，让图表和列表在首次演示时已有内容。

## 三、角色与业务过程

| 角色 | 常用页面 | 业务边界 |
|---|---|---|
| 挂号收费员 | 患者、排班挂号、接诊看板、收费台、收费记录与退费、凭证打印 | 不开方、不发药、不查审计 |
| 门诊医生 | 接诊看板、本人待诊、诊疗记录、常用诊断、处方、患者时间线 | 仅处理本人接诊，不收费、不发药 |
| 药房药师 | 药品批次、发药、库存预警与流水 | 仅已收费处方能发药，不修改药价 |
| 管理员 | 患者、排班、药品、导入、经营图表、审计、账号管理 | 不代替医生执业身份开方 |

正常过程：挂号产生排队号，医生接诊并保存文书，建立处方草稿，核对金额后提交，收费员收费，药师确认发药，患者就诊完成。处方还支持“已收费、未发药”时全额退费的分支。

挂号状态：候诊、就诊中、已完成、已取消。处方状态：草稿、待收费、已收费、已发药、已退费。仅草稿可修改；重复收费、重复发药和重复退费会被拒绝。

## 四、实现说明

前端采用React 19、TypeScript、Vite、shadcn/ui与lucide图标。深青侧栏、浅色工作区、统一按钮、卡片、表格和徽章贯穿所有页面。趋势图由SVG绘制，本版没有新增图表依赖。

后端保留FastAPI、SQLAlchemy、Alembic和SQLite。前端生产文件与API由同一进程提供，本机只需一个端口。数据库包含16张业务表，本版增加clinical_records、refund_orders、stock_movements，并补充收费方式字段。关系与字段见[数据字典](er.md)，接口见[接口说明](api.md)。

金额使用Decimal与单价快照。收费、批次扣减、处方状态和审计在同一事务；发药不再次扣库存。退费记录和原批次回库同事务。列表采用分页、关联批量加载，库存提醒采用聚合查询，不按每行逐次请求数据库。

本版后端修改用于支撑上述可见功能，未扩展数据库平台或重做架构。SQLite适用于本机课程演示，不将小样本验证推断为生产负载能力。

## 五、本机演示与数据

推荐在项目目录运行：

```powershell
.\start-showcase.ps1
```

浏览器打开 http://127.0.0.1:8000 。脚本使用当天日期建立独立展示库，保留其他日期的数据。同一天重复启动继续使用当天数据，不自动撤销已完成业务。需要全新练习场景时，用start-demo.ps1的-DatabasePath指定一个新的SQLite路径，并加-Showcase。

展示数据包括多个有业务的科室和医生、15位虚构患者、10种教学药品、7天业务、候诊/待收费/已收费/已发药记录，以及低库存、近效期和过期样例。生成时区间汇总为44次有效挂号、收费840.30元；现场操作后会变化。这些是初始化构造的教学场景，不是真实医院历史。

常用账号：admin.demo、doctor.demo、cashier.demo、pharmacist.demo，统一演示密码Demo123!。另有doctor.resp.demo、doctor.gi.demo用于展示多医生。课前按[5分钟演示脚本](demo-script.md)完整演练。

## 六、验证与交付

本地46项后端测试通过，应用语句覆盖率91.99%；20项前端测试通过，ESLint、TypeScript、Ruff和生产构建通过。收费列表补充处方状态后，另复测4项相关用例通过。新增前端检查直接覆盖文书保存、退费按钮和库存筛选/流水切换，见[测试报告](test-report.md)。

新展示库迁移和初始化、12项角色API读取已验证。用户选择将新页面浏览器视觉验收延后，因此尚未声称完成本版页面交互验收或打印实测。旧版CI的4项任务通过，浏览器任务因患者标签定位失败；本版修正标签关联，新CI结果以本次PR关联运行记录为准。

本版交付源码、10页可编辑答辩PPT、报告、需求矩阵、ER/接口、测试记录和演示脚本。班级、学号、成员分工与真实人工复核经历由提交者填写。AI协作过程见[开发记录](ai-development-log.md)。

## 七、边界

本项目不包含住院、真实医保/支付、PACS、区域平台、完整ICD字典或完整药库采购盘点。AI默认关闭，未将未调用的真实模型当作完成项。完整规范原文、PostgreSQL与生产性能验证不属于本版已完成成果。
