# 7 分钟现场演示脚本

演示只使用真实页面和虚构数据，不使用录屏、静态按钮或预填成功结果。

## 0:00-0:30 项目定位

说明规范依据和闭环：`排班号源 → 挂号 → 处方 → 收费扣库存 → 发药 → 审计`。说明后端负责权限、金额、事务和状态转换。

## 0:30-1:10 收费员登录和排班

用 `cashier.demo / Demo123!` 登录；打开“排班与号源”，日期填 `2099-01-01`、科室 ID 填 `1`，查询并指出总号源 2、剩余号源 2。

## 1:10-1:50 创建挂号

打开“挂号管理”，患者 ID 填 `1`、排班 ID 填 `1`，确认挂号；指出排队号 1，并说明号源已扣减。

## 1:50-2:40 医生开方

退出收费员，使用 `doctor.demo` 登录；处方页填写挂号单 ID 1、诊断 `J06.9 / 急性上呼吸道感染`、药品 ID 1、数量 2；创建草稿并提交为待收费。

## 2:40-3:40 收费和库存

使用 `cashier.demo` 登录收费台，输入处方 ID 1；指出服务端返回 `¥25.00`、状态 `completed`，说明金额为 `12.50 × 2`，且扣库存与收费在同一事务。

## 3:40-4:20 药房发药

使用 `pharmacist.demo` 登录药房发药，输入处方 ID 1；指出发药单状态 `completed` 和发药时间。

## 4:20-5:00 审计日志

使用 `admin.demo` 登录审计日志并刷新；指出 `registration.create`、`prescription.charge`、`prescription.dispense`。

## 5:00-5:40 权限和异常

展示收费员访问 `/api/admin/ping` 返回 403；展示库存不足返回 400 且收费单、处方和库存回滚；展示重复收费返回 409。

## 5:40-7:00 测试和答辩

展示 `pytest`、前端 Vitest、Playwright 和 CI；说明 Docker 本机不可用时以 CI 构建证据为准；说明 AI 只辅助开发/可选分诊，不自动诊断、开药或改变收费。
