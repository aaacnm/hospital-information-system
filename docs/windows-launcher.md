# Windows 双击启动与关闭

本轮按用户要求采用普通GitHub仓库方式交付。只新增CMD入口及其辅助脚本，不打包解释器，不发布便携包，不自动安装或修改系统Python、Node.js。

## 实现

- 启动系统.cmd：调用系统自带Windows PowerShell 5.1，首次准备项目依赖及前端构建，后台启动演示服务，健康检查成功后打开默认浏览器。
- 关闭系统.cmd：发送当前实例专用停止信号，等待Uvicorn正常退出，保留数据；不按进程名批量结束Python、Node或浏览器。
- demo-control.ps1：用项目独立环境、锁文件、实例标识、PID和本地监听归属管理启停，8000被占用时尝试到8010；已有健康进程则复用。
- backend/scripts/demo_server.py：复用现有迁移/seed/展示场景，在同一服务进程中响应私有文件停止信号。没有新增网页关闭接口或业务表。

默认目录：.venv、frontend/node_modules、frontend/dist、demo-data（含当天数据库、密钥、运行记录、缓存、日志与临时文件），均不提交Git。脚本没有个人电脑的硬编码环境路径，开发者可通过PythonPath指定已关联的项目环境；成功启动后会在本机运行记录中记住该环境。

首次需要用户电脑已有Python 3.11+和兼容Node.js，且能联网安装锁文件/requirements依赖。普通双击不会下载运行时安装器，不写全局环境或永久修改执行策略。CMD里的ExecutionPolicy Bypass仅作用于当次PowerShell进程。

## 本轮实际验证（2026-10-29）

| 场景 | 结果 |
|---|---|
| Windows PowerShell 5.1实际调用中文CMD，使用带空格的独立数据路径 | 成功构建frontend/dist，初始化后health=ok |
| 重复点击启动 | 复用PID129400与同一实例，没有新增服务 |
| 8000已有演示A，再启动独立演示B | B使用8001；关闭B后A仍健康 |
| 陈旧记录指向无关PowerShell进程 | 没有终止无关进程，也没有影响A |
| 关闭后再次关闭 | 正常提示无需重复关闭 |
| A停止后重新启动 | 新PID181320，之前创建的虚构患者记录保留 |
| 项目默认demo-data目录，首次指定现有项目环境后再次启动 | 无需再次传环境路径，可启动并复用进程 |
| 停止与收尾 | 原进程与venv入口均退出，8000/8001无监听，见本轮cleanup记录 |

新增Python脚本Ruff检查及格式通过，项目契约3项通过。前端未改业务代码，本轮实际生产构建通过；没有重复运行此前46项后端及20项前端业务测试。

本机复用现有D盘项目Python与Node和已安装依赖，没有为验证再安装一套依赖。首次全新电脑的联网依赖安装流程已实现，但未在另一台干净Windows上实测。

验证命令使用NoBrowser避免操作既有浏览器，自动打开默认浏览器的调用经过代码检查，本轮未进行浏览器页面/打印视觉验收。此参数不影响同学直接双击时自动打开网页。

测试数据和日志位于D盘click-launch-20261029独立任务目录，默认演示数据位于D盘项目demo-data。实测frontend/dist约0.42MiB、默认演示数据约0.29MiB、独立测试临时目录约4.34MiB。没有制作或上传运行时、依赖、数据库或大型归档。实际PID和占用记录见[evidence/windows-launcher.json](evidence/windows-launcher.json)。
