# 本机现场演示：5分钟 + 2分钟答辩
课前：在自己电脑运行 start-demo.ps1，打开 http://127.0.0.1:8000。当天初始化自动生成未来7天排班；无需公网。4个演示账号密码Demo123!。
演示使用本机演示库；不要现场删除数据库。需要干净演示可给启动脚本一个新的 -DatabasePath。

| 时间 | 操作 | 讲清楚/看到什么 |
|---|---|---|
| 0:00–0:25 | 展示题目与范围 | 三个门诊分系统部分功能，支撑挂号；虚构数据 |
| 0:25–1:05 | 收费员挂号 | 选择患者甲、当日医生/上午，看到排队号和号源减1 |
| 1:05–2:05 | 医生接诊 | 本人待诊点击接诊；甲药2份+乙药1份，后端自动金额28.00；提交 |
| 2:05–2:50 | 收费员核对收费 | 待办选择，检查明细/金额，收费成功；库存对应减少 |
| 2:50–3:25 | 药师确认发药 | 仅已收费可见；确认后有记录，库存不会再次减少 |
| 3:25–4:15 | 管理员审计与报表 | 按prescription.dispense筛选刚才记录；当天金额/挂号/发药同步 |
| 4:15–5:00 | 质量与边界 | 展示测试、并发与回滚结果；明确AI默认关闭、可选 |
| 5:00–7:00 | 答辩 | 为什么快照计价？为什么SQLite串行写？重复药品如何防负数？ |

随机抽查：
1. 收费员token调用/admin/ping为403（后端测试已有直接验证）。
2. 现场运行pytest，具体命令见README。
3. 库存不足后无收费单、处方未变、全部库存未扣，日志无虚假成功。
4. 解释AI协作记录、人工复核和未实现范围；不编造组员经历。
结束后终端Ctrl+C停止；确认8000端口不再由本次服务监听。
