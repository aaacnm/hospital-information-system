# 课程最终验收清单

## 环境和证据

- [ ] 只使用虚构演示数据，没有真实患者信息、密钥或凭据。
- [ ] 后端 `/health` 返回 `status=ok`，前端能打开登录页。
- [ ] Docker/CI 构建结果已保存；本机无 Docker 时使用 CI 日志，不口头声称通过。

## 权限验收

- [ ] 错误密码返回 401。
- [ ] 未登录访问 `/api/auth/me` 返回 401。
- [ ] 收费员访问 `/api/admin/ping` 返回 403。
- [ ] 医生只能开方，收费员只能挂号/收费，药师只能发药，管理员能查审计。

## 5 分钟业务闭环

- [ ] 收费员查询 `2099-01-01` 内科排班，记录剩余号源 `2`。
- [ ] 创建患者 1、排班 1 的挂号，排队号生成，号源变为 `1`。
- [ ] 医生创建 `J06.9` 处方并提交为 `待收费`。
- [ ] 收费员收费，服务端返回金额 `25.00`，库存从 `5` 变为 `3`。
- [ ] 药师发药，状态变为 `completed`。
- [ ] 管理员看到 `registration.create`、`prescription.charge`、`prescription.dispense` 审计记录。

## AI 页面验收（扩展功能）

- [ ] 任一登录角色可打开“智能分诊”页面并看到明确免责声明。
- [ ] 输入症状后返回候选科室、紧急程度、说明、来源和免责声明。
- [ ] 空输入、超长输入或疑似隐私信息不会被直接提交为有效建议。
- [ ] provider 超时、错误或不可用时显示固定“系统兜底”，不展示原始模型文本。
- [ ] AI 结果不会创建处方、改变收费金额、扣减库存或替代医生诊断。

## 异常和质量门禁

- [ ] 号源耗尽返回 409，不创建半条挂号单。
- [ ] 库存不足返回 400，收费单不生成，处方和库存全部回滚。
- [ ] 重复收费返回 409，不重复扣库存。
- [ ] `python -m pytest -q`（当前收集 22 个后端/契约用例）、Ruff、前端 lint/typecheck/Vitest/build 全绿。
- [ ] Playwright 主流程通过，失败 artifact 可打开。
- [ ] CI Dockerfile/Compose 构建通过；本地无 Docker 时保留 CI 证据。

## 答辩准备

- [ ] 能说明挂号扣号源、收费扣库存的事务边界。
- [ ] 能说明金额为何必须后端重算。
- [ ] 能展示 AI 生成代码经人工发现、修复和复测的真实问题。
- [ ] 能如实说明扩展功能和未实现范围。
