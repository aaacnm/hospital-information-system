# 老师面前怎么演示：5分钟操作稿

同学演示优先双击“启动系统.cmd”，网页会自动打开；结束双击“关闭系统.cmd”。第一次准备需联网，电脑须已装Python与Node.js，见[新手说明](../给同学看的使用说明.md)。已有开发环境仍可用start-showcase.ps1。先演示新功能，技术细节留给老师追问。所有患者、药品和历史记录均为虚构教学数据。

## 课前准备

1. 在代码目录运行 `.\start-showcase.ps1`，打开 http://127.0.0.1:8000 。需要重建前端时加 `-Build`。
2. 确认四个账号可登录，密码均为Demo123!。先自己演练一遍，再用新的独立库练习，避免正式演示时用完待办。
3. 将浏览器放大到适合投影的尺寸，打开新版10页PPT。新页面的浏览器验收尚待进行，课前须亲自检查布局和打印预览。
4. 展示版默认按当天日期建库。其他日期数据保留，同一天重复启动不会重置业务。不要删除旧库。

## 上台顺序

| 时间 | 登录与点击 | 现场讲一句 |
|---|---|---|
| 0:00–0:40 | admin.demo，工作台 → 经营数据看板，点近7天，再看科室分布 | “这是我们做的门诊系统，包含医生、收费和药房。图表统计当前演示业务，日期可以切换。” |
| 0:40–1:15 | 退出，doctor.demo → 接诊看板 → 对一个候诊患者点开始接诊 → 进入诊疗工作台 | “医生能看到候诊和正在接诊的患者，开始接诊后患者会进入右侧。” |
| 1:15–2:00 | 填入教学示例 → 保存诊疗记录 → 查看就诊时间线，返回后选诊断和药品、创建草稿、提交待收费 | “这里保存本次病情，也能回看就诊历史。选药后自动计算金额，提交处方后锁定本次记录。” |
| 2:00–3:10 | 退出，cashier.demo → 收费台，按刚才患者核对明细 → 选收费方式 → 确认收费 → 查看收费凭证 | “收费员核对患者和药品后记账，凭证可以打印或保存PDF，这里是模拟收费。” |
| 3:10–4:20 | 退出，pharmacist.demo → 药房发药，核对刚才患者并确认 → 库存预警与流水，点低库存/近效期，再切流水 | “药师确认已收费的处方。库存页能看到缺药、临期和过期药品，流水可以追到具体批号。” |
| 4:20–5:00 | 退出，admin.demo → 经营数据看板，点刷新；有时间再导出CSV或看审计 | “刚才的收费和发药会进入统计。系统还支持收费记录、未发药退费和批次回库。” |

不必为固定金额反复切换药品，直接按当前处方金额讲解。普通基础数据的两药计价例子是12.50×2+3.00×1=28.00元；展示场景的预置处方金额可能不同。

## 两个备用亮点

**退费：** cashier.demo → 收费记录与退费 → 找到“申请退费”按钮 → 写明原因 → 确认退费并回库。只选未发药处方。随后查看已退费徽章、凭证退费标记或库存“退费回库”流水。演示退费的处方不要再演示发药。

**打印：** 打开处方笺或收费凭证 → 打印 / 保存为PDF。无需真的使用打印机；取消浏览器打印对话框后继续。

## 老师可能追问

| 问题 | 简单回答 |
|---|---|
| 哪些数据是真实的？ | 页面数据来自演示数据库，患者和初始化历史都是明确标注的虚构教学场景，现场操作会保存。 |
| 为什么分角色？ | 医生开方、收费员收费、药师发药，菜单和接口都按角色限制。 |
| 金额怎么来的？ | 系统按药品单价和数量计算，处方保存当时的价格，改药品档案不改历史处方。 |
| 为什么发药时库存没有再减？ | 收费时已经扣过库存，发药只确认发药结果，防止重复扣减。 |
| 退费怎么处理？ | 未发药才允许整张处方退费，保留原收费单和退费原因，药品回原批次。 |
| 能直接用于医院吗？ | 这是本机课程项目，支付、医保和患者都是模拟场景。 |
| AI怎么用？ | 开发中有AI协助，记录如实保留。系统的外部AI分诊默认关闭，没有把未调用的模型当作完成。 |

演示结束：在启动服务的终端按Ctrl+C。若老师要求现场跑测试，按README命令操作，不需要把大部分讲解时间用于后端实现。
