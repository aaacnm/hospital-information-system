# AI 功能与医疗伦理合规说明

## 边界

AI 主要用于小步生成代码、测试和文档，所有输出必须人工审查、静态检查和自动化验证。智能分诊是扩展项，不是 MVP 通过条件。

系统不得让模型自动诊断、开药、修改处方、改变收费或扣库存，也不得读取真实患者身份信息、病历、支付信息或密钥。

## 智能分诊扩展

当前已实现扩展接口 `POST /api/triage`，输出固定结构；它仍不属于 MVP 核心闭环的通过条件：

```json
{
  "dept": "消化内科",
  "urgency": "普通",
  "notes": "建议尽快到院，由医生进一步判断",
  "disclaimer": "本建议由 AI 生成，仅供参考，请以医生诊断为准",
  "source": "llm"
}
```

约束：科室必须来自系统字典；请求超时 10 秒；网络、密钥、空输入、乱码或 JSON 解析失败返回固定兜底；Pydantic 校验结构；解析失败不展示原始模型文本；结果不会自动写入处方、收费或库存。

## 隐私和安全

- 测试、截图、PPT 和演示只使用虚构数据。
- API key、JWT secret、数据库连接串只从环境变量或云 Secret 读取。
- 日志不记录密码、JWT、完整身份证和手机号。
- 外部 provider 调用前必须脱敏；无法可靠脱敏时不发送。
- provider 失败不能阻断核心业务，也不能伪造 AI 判断结果。

## 人工复核

- [ ] 页面显示 AI 生成标识和免责声明。
- [ ] 覆盖正常、空输入、超时、错误 JSON、越界科室和紧急症状测试。
- [ ] 医生或人工审核后才能用于临床沟通。
- [ ] 记录 AI 发现、人工确认、修复和复测结果。
- [ ] 明确没有真实医保、PACS、电子病历或区域平台联调。

本次课程验收以确定性业务闭环为准；智能分诊虽已作为扩展实现，仍必须通过页面、接口、免责声明和 provider 失败兜底验收，不得用静态按钮或模型演示冒充交付。
